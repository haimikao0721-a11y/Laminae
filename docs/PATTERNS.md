# 说法模式

[中文](PATTERNS.md) | [English](PATTERNS.en.md)

`SKILL.md` 讲的是「怎么在一个仓库里找两边、怎么核」。这份文档讲的是**别每次重新发明**：真实文档里的说法就那么几类，每类怎么认、能用什么事实测、什么时候测不了，写下来省得从头想。

用法：在目标仓库里挑说法时先在这张表里找到对应的一行，照着配 `fact`。**表里没有的，先判断它能不能测，不要硬套一个已有的类型。**

---

## 三种可测程度

先分清这三件事，比记住具体类型重要。

| | 含义 | 处理 |
|---|---|---|
| **直接测** | 事实就是文档说的那个东西，数出来比一比 | 正常写进 `claims.json` |
| **弱化测** | 只能测到一个更弱的命题，比文档说的弱 | 可以写，**但要在 `label` 或 `source` 里写明弱在哪**，否则读者会以为全核了 |
| **测不了** | 判据不在仓库里，或者工具拿不到 | **不写**。告诉用户这条核不准，说明读过哪些文件 |

`SKILL.md` 里那条「禁止用一条 `path-exists` 或 `text-in-file` 代替」说的就是第二种：**弱化测必须自曝**。

判断标准一句话：**这条说法如果是错的，仓库里的什么东西会不一样？** 答不上来就是测不了。

## 总表

| 说法长什么样 | 例子 | 程度 | `fact` | 注意 |
|---|---|---|---|---|
| 精确数量 | 共 12 关 · 42 个图标 | 直接测 | `count-files` / `json-length` / `regex-count` | 默认 `eq` |
| 下限 | 1600+ · 至少 10 项 | 直接测 | 同上 + `compare: "gte"` | 差额大时会被标「措辞盖住」，见下 |
| 上限 | 最多 50 · 不超过 3 秒 | 直接测 | 同上 + `compare: "lte"` | 同上 |
| 近似 | 约 2000 · about 50 | 直接测 | 同上 + `compare: "approx"` | 默认容差 5%，数字小时要调 `tolerance` |
| 区间 | 1600–1800 个 | 直接测（拆两条） | 两端各一条，下限 `gte`、上限 `lte` | **一条说法只能捕获一个数** |
| 脚本 / 命令名 | `pnpm run build` | 弱化测 | `json-has-key`（package.json 的 `scripts`） | 只证明脚本登记了，不证明能跑 |
| 文件 / 目录路径 | `src/host.ts` · `packages/core` | 直接测 | `path-exists` | 改名追踪没有，改了路径会被当成消失 |
| 提到的标识符 | 用的是 `APIRouter` | 弱化测 | `text-in-file` | 只证明字符串在文件里，不证明在用 |
| 配置项 | `engines.node` 有最低版本 | 直接测 | `json-has-key` / `json-number` | 版本号是字符串，`json-number` 取不到 |
| 行数 / 体积 | 单文件 200 行以内 | 直接测 | `line-count` / `file-bytes` | 阈值型要用 `lte` |
| 测试通过 | 42 个测试全过 | 直接测 | `test-passes` | 见下节，是最贵也最值钱的一种 |
| 行为不变 | 重构不改变输出 | 直接测 | `output-unchanged` | 只比 stdout，写进文件的不算 |
| 业务不变量 | 分项加总等于总额 | 直接测 | `invariant-holds` | 判据要自己写 |

## 每类的具体做法

### 数量

先问「数得出来吗」，再问「数哪个」。

- 文件数 → `count-files`，`glob` 里 `*` 不跨目录、`**` 跨目录
- JSON 里的数组长度或对象键数 → `json-length`
- 某个文件里某个模式出现几次 → `regex-count`
- 文件行数 → `line-count`

**常见坑**：文档说「17 个图标」，`assets/art` 里同时有 png、ico、gif。**先数清楚文档指的是哪几种**，`glob` 写成 `assets/art/*.png` 而不是 `assets/art/*`。数错了比不数更糟，因为会给出一个错的绿格子。

### 下限与近似

`gte` 只判方向，**不判断文档写的下限是不是太保守**。README 写「1000+」、实际 1539，`gte` 下仍是真。想在「写得太旧」时报警，得用 `approx` 或写精确值。

工具会把「措辞像下限、却按严格相等比较」的说法在终端和页面上列出来，但**不会自动改判定**——文档写的到底是下限还是精确值，只有人知道。

下限还有一个副作用：相对差额 ≥15% 且绝对差 ≥2 时，会记成「措辞盖住差额」。这两个数是人为定的，见 [REFERENCE.md](REFERENCE.md)。

### 区间

「1600–1800 个」捕获不了两个数。拆成两条：

```json
{ "id": "size-min", "locator": "(\\d+)\\s*[–-]\\s*\\d+ 个", "compare": "gte", ... }
{ "id": "size-max", "locator": "\\d+\\s*[–-]\\s*(\\d+) 个", "compare": "lte", ... }
```

两条独立判定，可能一真一假，这比合成一条更接近事实。

### 命令与脚本

`json-has-key` 指向 `package.json` 的 `scripts`，只能证明**登记过**。命令能不能跑、跑起来对不对，不在这个类型的范围里。

真要证明能跑，用 `test-passes` 去跑它——但那要执行命令，见下节。

### 测试、不变量、输出差分

这三种**会执行命令**，是唯一能碰到函数体里算出来的数的办法。代价和风险都比前面几种高。

| 类型 | 为真 | 适合什么说法 |
|---|---|---|
| `test-passes` | 退出码 0 | 「这个功能在」「这个接口这么用」——仓库里有对应测试 |
| `invariant-holds` | 退出码 0 | 「分项加总等于总额」「酬金不为负」——性质由你写成校验脚本 |
| `output-unchanged` | stdout 与基线相同 | 「重构不改变行为」——文档说不该变，看它变没变 |

必读的几条：

- **一定要写 `watch`。** 不写就每个 commit 都跑一遍，几百个 commit 的仓库会跑很久。`watch` 填命令真正读的文件（glob），内容没变就复用上次结果。
- **超时或起不来记「测不出来」，不记成失败。** 这是有意的：看不见不能说成没问题，也不能说成有问题。
- **命令在临时 worktree 里跑，权限和运行 laminae 的人一样。** 不要写会改系统、会删数据的命令。
- **多个仓库并行时会自动改成串行。** 测试会抢端口、抢测试库，同时跑互相打架，失败还会被记成「测不出来」——看起来像工具坏了。

### 测不了的常见几类

这些在真实文档里很常见，但**现在测不了**，不要去凑一个弱化版充数：

| 说法 | 为什么测不了 |
|---|---|
| 「性能提升 3 倍」 | 需要可复现的基准和硬件环境 |
| 「支持 macOS / Linux」 | 除非 CI 配置里明确列了，否则只是字符串 |
| 「用起来很简单」 | 判据是人的感受 |
| 「42 个测试全部通过」的**数字** | 能测「某一条测试过不过」，数不出「一共几条在过」——那要跑全量并解析输出 |
| 「生产环境跑了 6 个月」 | 仓库里没有运行记录 |
| 「改进了错误处理」 | 判据是行为对比，不是文件形状 |

遇到这些，**停下来告诉用户「这条核不准」，并说明读过哪些文件**。不要退回到 `text-in-file`——那会让读者以为核过了。

## 往表里加东西的规矩

这张表是要长的，但只能是**验证过的**才往里加。

1. **先在真实仓库上跑过。** 挑到一个新模式，至少在两三个不同仓库上试，确认这个 `fact` 组合能真数出东西。
2. **写清楚弱在哪。** 「弱化测」那几行必须有一句说明它比原说法弱多少。
3. **记下已知误报。** 比如「1600+ 而实际 1899 会被标成措辞盖住，但读者可能认为没问题」。误报率现在还是分类型记的，没有合并成一个数。
4. **不写「以后再做」的类型。** 表里只放现在能跑的，否则 `SKILL.md` 那句「禁止用表层检查冒充」就失效了。

## 和 `suggest.ts` 的关系

`suggest.ts` 从 Markdown 里按字面捞候选（下限、近似、命令、精确数），产出的是**草稿**——`fact` 多半是占位的，要人改过才能用。这张表是改的时候查的。

流程是：

```
node src/suggest.ts          # 捞草稿，打印 JSON，不写文件
node src/lookup.ts 草稿.json  # 在 HEAD 上查：捕获到什么文本、事实现在测到多少
# 对不上就改 locator 或 fact，再 lookup 一遍
# 都对上了，再放进 .laminae/claims.json
```

**跳过 `lookup` 直接写进 `claims.json` 是错的**：`suggest` 只按字面猜，不看仓库里到底有没有那个东西。第一次跑出来一片红，多半就是这一步没做。
