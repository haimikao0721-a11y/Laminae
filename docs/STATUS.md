## 四、已知的坑（按严重程度）

### 1. `.vue` 文件里的引用看不见

**现象** vue 上最后剩 4 条孤立，全部是同一个原因：引用它们的是 `.vue` 文件。

```js
// packages-private/sfc-playground/src/Header.vue
import { downloadProject } from './download/download'
```

`.vue` 不在代码文件范围内，这条边根本不存在，于是 `download.ts` 看起来没人用。

**影响** 任何 Vue / Svelte / Astro 项目都会有这一整类误报。

**要修得会读 SFC 的 `<script>` 块**，不是补个规则的事。

---

### 2. 「往下看一层」有一整类误报

**现象** vue 上「当前成立」原本 12 条。修掉注释遮罩和类型声明之后剩 3 条，全是设计如此的代码：

| 例子 | 为什么是误报 |
|---|---|
| `shared/src/general.ts:13  NO  return-const` | `export const NO = () => false`，文档写着 "Always return false."，是有意的常量谓词 |
| `compiler-sfc/src/index.ts:89  shouldTransformRef` | `() => false`，功能开关，暂时关掉 |
| `runtime-core/src/apiWatch.ts:186  watchStopHandle` | 空句柄，后面挂 `.stop` / `.resume` 保持 API 形状 |

已经修掉的两类：注释和字符串里的代码样例（`xxx`、`NODE`、`foo`）、类型声明文件（`declare function`）。

**影响** 箭头常量函数、类型声明、解析伪影，这三类会一直被报。

**为什么没修** 它和前面几个不是同一个根因（不是「按设计如此」，而是「解析错了」），需要单独设计。硬塞进去会把真正的空壳一起漏掉。

---

### 3. graph 阶段占 79% 的时间

**已解决。** 原来整条流水线 1397 秒，graph 一步 1102 秒。四轮改动之后：

```
每 commit      212.5 ms → 63.8 ms（3.3 倍）
端到端         1397 秒 → 465 秒
graph 一步     1102 秒 → 269 秒（4.1 倍）
```

四轮分别是：换掉回溯正则（1.04 倍）、增量只处理变了的文件（2.05 倍）、
6513 次 git 调用换成 2 次（3.10 倍）、遮罩改切片（3.33 倍）。
细节和踩过的坑见 [踩过的坑](LESSONS.md)。

**剩下的热点**（3 倍提速之后重新 profile 的第一名）是 `maskNonCode`，29.8%。
但它和上一次一样：profile 的百分比不等于可回收的时间，合并之后墙钟没有明显变化。
**再往上要动的不是微优化，是能不能少扫几遍。**

---

### 4. `hops` 在分叉的树上会偏小

**现象** `hops` 记的是「离最近空壳的距离」。在一条直链上是准的（实测四层链：`deep(1) mid2(1) mid1(2) top(3)`），但在分叉树上，一个函数经由不同路径到达空壳的距离不同，只记一个数会丢掉这个信息。

**影响** 目前只影响置信度标注，不影响真假判定。

---

### 5. 隔离型事实要工作区

`test-passes`、`invariant-holds`、`output-unchanged` 三类要执行命令，会建临时工作区，跑完删掉，不动主目录。**分支扫描里也一样跑** —— watch 的文件没变就不重跑。

## 六、这个工具的边界

**它核对，不体检。**

- **核对**：文档说 X，去代码里查 X 是不是真的。这类输出在真实仓库上没出过错。
- **体检**：工具自己觉得哪里有问题，然后报告。这类输出在真实仓库上整类整类地错过。

判断一个功能属于哪一类，看它有没有**出处**：

| | 核对 | 体检 |
|---|---|---|
| 谁提出的 | 文档自己 | 工具 |
| 有没有出处 | 有，指得出哪一行 | 没有，是启发式 |
| 错了谁知道 | 一跑就露 | 没人知道 |

**体检类输出要么取证，要么别以「问题」的形态出现。** 这是这一路最贵的一课，详见 [踩过的坑](LESSONS.md)。
