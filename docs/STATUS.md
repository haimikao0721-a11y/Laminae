### 为什么选这几个

- **click**：Python、有真实的历史包袱（单文件 → 多文件重构）、有教科书式的抽象方法、1207 次合并。它是第一个让我发现「工具会整类整类误报」的仓库。
- **vue**：明显更大的规模（4.7 倍 click 的主线提交数），TS monorepo，用来压性能。
- **django 没选**：34072 个主线提交 × 7089 个文件，每个 commit 都要 `ls-tree` 全树，估算要几十小时。

## 四、已知的坑（按严重程度）

### 1. `.vue` 文件里的引用看不见

**现象** vue 上最后剩 4 条孤立，全部是同一个原因：引用它们的是 `.vue` 文件。

```js
// packages-private/sfc-playground/src/Header.vue
import { downloadProject } from './download/download'
```

`.vue` 不在代码文件范围内，这条边根本不存在，于是 `download.ts` 看起来没人用。

**影响** 任何 Vue / Svelte / Astro 项目都会有这一整类误报。

**要修得会读 SFC 的 `<script>` 块**，不是补个规则的事。

---

### 2. 「往下看一层」有一整类误报

**现象** vue 上「当前成立」12 条，抽样看基本都是误报：

| 例子 | 为什么是误报 |
|---|---|
| `shared/src/general.ts:13  NO  return-const` | `export const NO = () => false`，惯用写法 |
| `compiler-core/src/babelUtils.ts:468  NODE  empty` | 从对象字面量里解析出来的伪函数 |
| `dts-test/*.test-d.ts  expectString` | 类型声明 `declare function`，本来就没有函数体 |

**影响** 箭头常量函数、类型声明、解析伪影，这三类会一直被报。

**为什么没修** 它和前面几个不是同一个根因（不是「按设计如此」，而是「解析错了」），需要单独设计。硬塞进去会把真正的空壳一起漏掉。

---

### 3. graph 阶段占 79% 的时间

**现象** vue（6513 个主线提交）上：

```
measure      290s
graph       1102s   ← 79%
ideas          3.6s
build-data     0.5s
render         0.2s
verify         0.9s
```

**影响** 规模再大一倍就跑不动了。django 那种体量直接排除。

**下一个要优化的点很明确。**

---

### 4. `hops` 在分叉的树上会偏小

**现象** `hops` 记的是「离最近空壳的距离」。在一条直链上是准的（实测四层链：`deep(1) mid2(1) mid1(2) top(3)`），但在分叉树上，一个函数经由不同路径到达空壳的距离不同，只记一个数会丢掉这个信息。

**影响** 目前只影响置信度标注，不影响真假判定。

---

### 5. 隔离型事实要工作区

`test-passes`、`invariant-holds`、`output-unchanged` 三类要执行命令，会建临时工作区。分支扫描里直接跳过它们，记成「测不出来」——**不假装查过**。

## 六、这个工具的边界

**它核对，不体检。**

- **核对**：文档说 X，去代码里查 X 是不是真的。这类输出在真实仓库上没出过错。
- **体检**：工具自己觉得哪里有问题，然后报告。这类输出在真实仓库上整类整类地错过。

判断一个功能属于哪一类，看它有没有**出处**：

| | 核对 | 体检 |
|---|---|---|
| 谁提出的 | 文档自己 | 工具 |
| 有没有出处 | 有，指得出哪一行 | 没有，是启发式 |
| 错了谁知道 | 一跑就露 | 没人知道 |

**体检类输出要么取证，要么别以「问题」的形态出现。** 这是这一路最贵的一课，详见 [踩过的坑](LESSONS.md)。
